I spent six months building an AI coding agent. Three months in, I almost killed it.

The models were fine. Claude writes decent code. GPT writes decent code. The problem was the architecture. Every design I drew had a server sitting between your repo and the model. That server had to clone your code, read it, generate diffs from it. And the moment it existed, it became a target. A liability. Something you had to audit and pray nobody breached.

I would not use a tool that proxies my source code through someone else's machine. So I could not build one.

**What is ShipNap?** ShipNap is an AI coding agent that connects to your GitHub repo, writes code while you sleep, and opens a pull request — without ever proxying your source code through a third-party server. You bring your own API key, pick any model (Claude, GPT, Gemini), and ShipNap handles only orchestration. Your code moves directly from GitHub to the model provider and back to a PR branch. Nothing sits in the middle.

## The Security Problem With AI Coding Tools

Every AI coding tool does the same thing under the hood. It reads your code, sends it to a model, gets suggestions back. The differences are UI. Tabs vs chat. Inline vs sidebar. But the architecture is identical: a service sits between your repo and the model.

For side projects, fine. For a real codebase with real customers and real compliance requirements? Hard no for most teams I talk to. Legal kills it before the first commit.

Here is the part that gets weird. The AI companies already solved the trust side. Anthropic does not train on API traffic. OpenAI does not train on API traffic. Google does not train on API traffic. The model providers are not the risk. The proxy is.

So I asked: what if there was no proxy?

## How it works

ShipNap handles orchestration only. It clones your repo, creates a branch, coordinates the agent loop. But the inference calls go directly from your API key to the model provider. Your code moves from GitHub to Claude, or GPT, or Gemini, and back to a PR branch. ShipNap never touches it.

What that means in practice:

- No source code stored, cached, or logged on our servers
- No vendor lock-in. Bring your own key, pick any model, switch any time
- No markup. Your provider bills you at their standard rate
- No black-box prompts. You can inspect and tune the system prompt yourself

You need an API key. For the people this is built for, that is not a downside. It is table stakes.

## Does it work?

Sometimes. Sometimes it does not. Same as every AI tool.

It does well on scoped tasks. "Add rate limiting to the login endpoint." "Migrate the user table for avatar_url." "Write tests for the billing module." You get a PR with commit messages, test output, and notes on anything non-obvious it decided.

On large ambiguous tasks it struggles. Same as a human junior dev who got a vague ticket at 4:45 PM on a Friday. The models are not magic. They are tools. Good ones, improving fast, but tools.

I am saying this because the AI coding space is drowning in hype. Everything is revolutionary, game-changing, the future of software. Most of it ships features the models wrote three months ago and nobody reviewed. I am not bitter. I am just someone who has used these tools enough to know when they help and when they burn my time.

## Why BYOK matters

Bring Your Own Key is not a pricing decision. It is an architectural one.

When you hold the key, the threat model collapses to something manageable. The orchestration layer cannot read your code because it does not proxy the calls. Only three parties ever see your source: your repo, your machine, and the model provider. Who, again, is not training on it.

You also control the model. Different tasks want different models. Claude Opus for architecture refactors. GPT for straightforward CRUD. Gemini when you need a 2M token context window. With BYOK you switch per task. Nobody else decides for you.

And yes, the cost difference is real. A $30 subscription that caps you at 50 requests a day versus $20 in API credits that gets you hundreds of calls on the latest model. The math is not subtle.

## FAQ

### Is ShipNap safe to use with production code?

ShipNap never stores, caches, or logs your source code. The orchestration layer clones your repo and creates a branch, but all inference calls go directly from your API key to the model provider — Anthropic, OpenAI, or Google. Those providers do not train on API traffic. For teams with compliance requirements, this architecture means your code never sits on a third-party server between your repo and the model.

### Which AI models does ShipNap support?

Any model available via API. Claude Opus and Sonnet from Anthropic. GPT-4o and GPT-5 from OpenAI. Gemini from Google. You bring the key, you pick the model, you switch any time. Different tasks call for different models and ShipNap does not lock you into one.

### How does bring-your-own-key (BYOK) work?

You provide your API key during setup. When ShipNap runs a task, the inference calls go from your key directly to the model provider. ShipNap never proxies those calls. You pay the provider at their standard rate — no markup. You can rotate or revoke your key at any time.

### Does ShipNap replace Copilot or Cursor?

No. Copilot and Cursor are interactive tools you use while coding — inline autocomplete, chat, code generation in your editor. ShipNap runs asynchronously. You describe a task, deploy it, and come back to a PR. They complement each other. Many teams use both.

A typical Claude API call for a scoped task costs a few cents. Compare that to $20-30/month subscriptions that cap you at 50-100 requests a day and the cost difference adds up fast.
